# 产品需求文档（PRD）

> 状态：草案 · 最后更新：2026-09-08

## 1. 产品愿景

Deva 是一款面向开发者的**桌面端 AI 原生开发工作台**。它将 AI 编码智能体（Agent）作为开发流程的一等公民，围绕 Agent 构建一套完整的开发工具集，让开发者在**同一个应用**内完成「与 AI 协作写代码」与「使用专业 IDE 工具」的全部工作。

一句话定位：**把 Claude Code 的 Agent 能力，装进一个 IDEA 级别的开发工具箱里，用 Codex 式的清爽界面呈现。**

### 设计信条

1. **Agent 优先，工具环绕**：主体交互是与 Agent 对话/协作，IDE 工具是 Agent 与人共享的能力面板。
2. **可控与可信**：AI 的每一次危险操作都可被感知、可被拦截。权限透明、操作可回溯。
3. **专业不臃肿**：具备 IDE 的专业深度，但界面遵循 Codex 的克制美学，避免功能堆砌。
4. **开放可扩展**：通过 Skill、MCP、子 Agent、多 Provider 保持能力开放，不锁定单一模型或生态。
5. **本地优先**：核心工作在本地完成，数据与凭据默认不出本机（除用户显式调用的云端模型/服务）。

## 2. 目标用户

| 画像 | 描述 | 核心诉求 |
| --- | --- | --- |
| **全栈 / 后端工程师** | 日常在 IDE 中写代码、连数据库、调远程服务器 | 希望 AI 深度参与编码，同时不离开熟悉的 DB/终端/SSH 工具 |
| **AI 应用开发者** | 构建 Agent、集成 MCP、调试提示词与工具 | 需要一个能编排 Skill/MCP/子 Agent 的强力宿主 |
| **DevOps / SRE** | 频繁 SSH 到远程、执行运维命令、查缓存/数据库 | 需要远程终端 + 数据库 + AI 辅助排障三合一 |
| **技术团队负责人** | 关注可控性、合规、私有化 | 需要权限管控、私有模型接入、数据不出域 |

**非目标用户**：纯小白/非技术用户；重度依赖特定语言专有重型插件生态（如需完整 JetBrains 插件市场）的用户——初期不覆盖。

## 3. 竞品与差异化

| 维度 | Claude Code | Codex | IntelliJ IDEA | **Deva** |
| --- | --- | --- | --- | --- |
| 形态 | CLI / 终端 | CLI / Web | 桌面 IDE | **桌面 App** |
| Agent 能力 | ★★★（Skill/MCP/子Agent/权限） | ★★★ | ★（插件） | **★★★（对齐 Claude Code）** |
| 模型 | Claude | 多模型 | 插件依赖 | **多 Provider 抽象** |
| 数据库工具 | ✗ | ✗ | ★★★ | **★★（MySQL/Redis）** |
| 终端 / SSH | 部分 | 部分 | ★★★ | **★★★** |
| Git 集成 | 命令级 | 命令级 | ★★★ 图形化 | **★★ 图形化** |
| 界面 | 无 GUI | 简洁 | 功能密集 | **Codex 主体 + IDEA 工具窗口** |

**差异化定位**：市面上要么是「强 Agent 但无 IDE 工具」（Claude Code / Codex），要么是「强 IDE 但 Agent 是插件外挂」（IDEA）。Deva 的差异点是**把两者以 Agent 为中心原生融合**。

## 4. 功能范围

功能按优先级标注：`P0`（MVP 必须）、`P1`（重要，紧随其后）、`P2`（增强）。详细排期见 [路线图](./roadmap.md)。

### 4.1 AI Agent 核心

| 功能 | 优先级 | 说明 |

| Agent 对话与任务执行 | P0 | 与 Agent 对话，Agent 通过工具调用完成编码任务 |
| 多 Provider 接入 | P0 | 默认 Claude；支持 OpenAI、Ollama、OpenAI 协议兼容端点 |

## 5. 关键用户场景（User Stories）

1. **AI 辅助改 Bug**：开发者打开工作区 → 向 Agent 描述 Bug → Agent 搜索代码、读文件、提出修改 → 每处写操作经权限确认 → 修改以 diff 呈现 → 开发者接受后 Agent 运行测试 → 用 Git 面板提交。
2. **远程排障**：SRE 通过 SSH 连接线上机器 → 打开集成终端查看日志 → 让 Agent 分析日志 → Agent 在授权下查询 Redis 缓存状态 → 给出结论。
3. **数据核对**：后端开发连接 MySQL → 执行查询核对数据 → 让 Agent 根据结果生成修复脚本 → 审核后执行。
4. **扩展能力**：AI 应用开发者接入公司内部 MCP 服务 → Agent 获得新工具 → 编写 Skill 固化常用工作流 → 用子 Agent 并行处理多个模块。

## 6. 非功能性需求

| 维度 | 要求 |
| --- | --- |
| **性能** | 冷启动 ≤ 3s（目标）；大文件/大结果集虚拟化渲染；Agent 流式首字延迟低 |
| **安全** | 渲染进程无 Node 权限（contextIsolation）；密钥加密存储；权限默认最小化 |
| **稳定** | 单个工具/连接崩溃不影响主进程；关键操作可撤销 |
| **可维护** | monorepo 分层清晰、包边界明确、核心逻辑可脱离 UI 测试 |
| **隐私** | 本地优先；明确告知哪些数据会发往云端模型 |
| **可访问性** | 键盘可达、对比度达标、支持缩放 |

## 7. 非目标（Out of Scope）

- 不做完整的 JetBrains 插件市场兼容。
- 初期不做移动端 / Web SaaS 版本（桌面优先）。
- 初期不内置代码补全式 Copilot（重心在 Agent 协作，而非行内补全）；可作为远期 P2。
- 不做团队协作/多人实时编辑（远期考虑）。
- 不做除 MySQL / Redis 之外的数据库（初期）。

## 8. 成功指标（初步）

- **激活**：新用户能在 10 分钟内完成「打开工作区 → 与 Agent 完成一次带权限确认的代码修改」。
- **留存**：核心用户每周使用 ≥ 3 天。
- **可信度**：无「未经确认的破坏性操作」事故。
- **扩展性**：能成功接入至少一个外部 MCP 服务并被 Agent 使用。

## 9. 开放问题

- 代码编辑器选型：Monaco（功能强、体积大）vs CodeMirror 6（轻、可定制）——见 [技术栈](../architecture/tech-stack.md)。
- 是否需要内置 LSP 以提供跳转/诊断？初期倾向轻量，靠 Agent + 基础高亮。
- 子 Agent 的资源与并发上限策略。
- 计费/用量统计是否需要内置（多 Provider 下的 token 计量）。
